# JAM LAB — 渋滞の科学

1台1台の車を計算する交通シミュレーションで、渋滞が生まれる仕組みを遊びながら発見するゲームです。iPhoneのSafariで遊ぶことを最優先に作っています（PCでも遊べます）。

- 起動方法：このリポジトリを静的Webサーバーで配信して `jam/` を開くだけです。ビルドはいりません。
  - 例：リポジトリ直下で `python3 -m http.server 8000` を実行し、`http://localhost:8000/jam/` を開く
  - GitHub Pagesで公開している場合のURLは `https://<ユーザー名>.github.io/godzilla-quiz/jam/` です
- iPhone：Safariで開き、共有メニューの「ホーム画面に追加」で全画面のアプリとして起動します（PWA）。一度開けばオフラインでも遊べます。
- セーブデータは端末内（localStorage）に保存します。ログイン・課金・AI APIは使っていません。

## 交通モデル

- **車の追従**：IDM（Intelligent Driver Model）の改良版 IIDM と、割り込み直後の過剰反応を抑える ACCモデル（Enhanced IDM）。全車が自分の位置・速度・実際の加速度・目標速度・車間時間・最小車間・最大加速度・快適減速度を持ちます。
- **人間らしさ**：反応・ペダル操作の遅れ（実際の加速度が指示値に一次遅れで追従）と、ゆっくり変化する運転のゆらぎ（Ornstein–Uhlenbeck過程）。運転手タイプは 慎重／平均的／車間が短い／協調自動運転。車種は乗用車・トラック・バス。
- **車線変更**：MOBIL（安全条件＋利得判定、左側通行のため左車線を基本）。ウインカー → 0.8秒後に再判定 → 3秒かけて横移動。合流・車線減少は義務的な車線変更として扱い、加速車線では隙間を探して速度を合わせます。
- **その他**：サグ部（坂に気づかず加速が足りない効果）、トンネル等の速度低下区間、渋滞を経験した運転手の車間がやや長くなる記憶効果（容量低下 capacity drop）、信号（黄の判断はジレンマゾーンで一度だけ決定）、ランプメーター（1台ずつ停止・発進）、事故車による車線閉塞。
- **数値計算**：固定時間刻み 0.05秒、乱数はシード付き（流入・車ごとのゆらぎで別系列）。状態はすべてプレーンなデータなので、まるごと複製して「対策なし」の双子を同時に走らせられます。再生速度を変えても計算刻みは変わりません。最後の安全装置として「前の車に食い込まない」制約がありますが、テストではこの装置が一度も働かないことを確認しています。
- **指標**：平均速度＝空間平均、密度＝台数÷（区間長×車線数）、流率＝速度の合計÷（区間長×車線数）（Edieの定義、流率＝密度×速度が厳密に成立）。基本図の点は区間ごとの総走行距離と総滞在時間から求めます。渋滞は高速道路で時速40km以下（円形道路は「一様な流れの速度の半分未満」）、遅れ時間は基準速度との差（入口で待つ時間を含む）。

### 計算で確認した主な結果（このモデルでの値）

- 円形道路 400m・目標50km/h：22台以下ではそのままでは安定。22台で1台が2秒ブレーキすると渋滞が生まれて残り、24台以上では誰も操作しなくても自然渋滞が発生します。渋滞の波は時速およそ10〜16kmで後ろへ進みます（実際の高速道路での観測値は15〜20km程度）。
- 協調自動運転車を2割混ぜ「渋滞吸収走行」にすると、26台でも止まってしまう車がいなくなり、平均速度も上がります。
- 2車線の高速道路：渋滞前の最大流率は約3,500台/時、渋滞後の捌け交通量は約2,900〜3,200台/時（容量低下）。
- 施策の効果（各ステージの固定シードで、対策なしとの比較）：サグ部での速度回復の呼びかけ＋左車線利用で遅れ約46%減、路肩活用で約59%減、ランプメーター700台/時で本線の遅れ約31%減（ランプ待ちは30秒→47秒）、信号サイクル140秒→100秒・東西60%で約27%減。
- 正直な結果として、**ファスナー合流**と**一律の速度制限**は、このモデルでは遅れを減らしませんでした（条件しだい・場合によっては悪化）。ゲーム内でもそのまま反映され、解説でも「効果は条件しだい」と説明しています。

## 単純化していること

これは理論モデルによるシミュレーションで、実在の道路の予測ではありません（ゲーム内の「しくみ」にも記載）。
高速道路は画面に収めるために折りたたんで描いていますが、計算上は直線道路です（カーブでの減速なし）。円形道路は1車線、自動運転車の制御は単純化したものです。

## ファイル構成

- `js/sim/` 交通エンジン（`engine.js` 本体、`models.js` IDM/MOBIL等、`scenarios.js` 道路、`rng.js` 乱数）— DOMに依存せずNode.jsでも動きます
- `js/game/` ミッション定義・採点、施策と操作の対応、原因クイズ
- `js/render/` Canvas 2D 描画（道路配置、車のスプライト、重ね表示、グラフ）
- `js/ui/` 画面・操作、テキスト、セーブ、効果音（すべてプログラムで合成）
- `tests/` テスト、`tools/` アイコン生成

外部ライブラリは使っていません（React等のビルドが必要な構成にせず、リポジトリの他のアプリと同じく静的ファイルのまま公開できる形にしました。シミュレーションと描画は別モジュールに分離しています）。

## テスト

- `node --test tests/*.test.js`（`jam/` で実行）：低密度で安定／高密度で自然渋滞／停止波の逆方向伝播／車間時間の反映／ブレーキ連鎖／自動運転車による波の減衰／ランプ交通量の本線への影響／施策が指標に反映されること／車の重なり・瞬間移動・逆走がないこと（円形・合流・車線減少・交差点）／同じシードで同じ結果・一時停止しても同じ結果・複製が同じ経路をたどること／全8ステージが★2以上でクリア可能／クイズの全6シナリオで実際に渋滞が起きること。
- `node tests/e2e.mjs [URL]`：iPhone 13 相当（Playwright + Chromium、タッチ操作）でチュートリアル（タップ→ブレーキ長押し→結果）、スライダー、一時停止と¼倍速、表示切替、ステージ1を最後まで、再読み込み後のスター保持、合流ステージの早送りと比較表、クイズ、iPhone SE サイズと横向き、Service Worker、JSエラーなし を確認します。
- 実機のiPhoneでは確認していません（エミュレーションのみ）。
